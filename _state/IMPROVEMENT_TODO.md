All implementation items start unchecked. Production permissions, deployments, scheduled jobs, and performance still need verification; source findings alone do not establish production exposure. Existing uncommitted fixes should be reconciled with these tasks before duplicating work.

Use the task IDs in branches, commits, and follow-up discussions. When starting a task, append `In progress — owner — branch/PR` to its entry. For a blocker, append `Blocked — reason — next action`. Check an item only when its completion criteria are verified; record the date, evidence, and deployment status in the log below. A local fix awaiting required deployment stays unchecked. Product experiments can be completed with a recorded decision to keep, revise, or stop them.
